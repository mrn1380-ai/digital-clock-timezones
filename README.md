# داشبورد تحلیل اسپرد و هزینه‌ی معاملات نوبیتکس

هدف: پاسخ به این سؤال که **«کارمزدِ واقعیِ معامله در هر نماد نوبیتکس چقدر است، آیا تفاوت نمادها معنادار است، و عاملِ این تفاوت چیست؟»**

اسپرد (فاصله‌ی بهترین خرید و فروش) «کارمزد پنهان» است و معمولاً از کارمزدِ اسمیِ صرافی بزرگ‌تر است. این پروژه تمام
نمادها را در یک لحظه (و در طول زمان) می‌گیرد، توزیع اسپرد را بررسی می‌کند، تفاوت گروه‌ها را با آزمون‌های آماری می‌سنجد،
سهم هر عامل را با رگرسیون جدا می‌کند و نمادها را در خوشه‌های هم‌سنخ تفکیک می‌کند.

## اجرا

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # خروجی production
npm test           # تست محاسبات (داده شبیه‌سازی‌شده) + تست رندر تمام تب‌ها
```

## منبع داده و محدودیت محیطی

| مورد | توضیح |
| --- | --- |
| اندپوینت اصلی | `GET https://apiv2.nobitex.ir/market/stats` (عمومی، بدون توکن، محدودیت ۲۰ درخواست/دقیقه). بدون پارامتر = آمار همه‌ی بازارها |
| اندپوینت عمق | `GET https://apiv2.nobitex.ir/v3/orderbook/all` (دفتر سفارشات همه بازارها) |
| جایگزین‌ها | `api.nobitex.ir`، پروکسی‌های عمومی CORS (AllOrigins، corsproxy.io، r.jina.ai)، و تیکرهای نوبیتکس در CoinGecko |
| نکته مهم | محیط اجرا (سرور توسعه) دسترسی مستقیم به اینترنت ندارد؛ بنابراین **همه‌ی فراخوانی‌ها از مرورگر شما** انجام می‌شود. اگر نوبیتکس از خارج ایران مسدود باشد، زنجیره‌ی جایگزین به ترتیب امتحان می‌شود |
| مسیر دستی | در «گزارش اتصال» می‌توان خروجی JSON را مستقیماً Paste کرد |

## متدولوژی

۱. **اسپرد**: `spread% = (bestSell − bestBuy) / mid × 100` که `mid = (bestSell + bestBuy)/2`.
۲. **هزینه کل**: برای تیکرِ رفت‌وبرگشت `spread + 2 × fee`؛ برای یک‌طرفه `½spread + fee`؛ میکر اسپرد نمی‌پردازد.
   کارمزدها طبق جدول ۷ سطحی نوبیتکس (پایه تا VIP6) و تفکیک بازار ریالی/تتری اعمال می‌شود و از UI قابل تغییر است.
۳. **توزیع**: چون توزیع اسپرد نرمال نیست (چولگی مثبت و دنباله‌ی سنگین)، گزارشِ اصلی روی **میانه و چارک‌ها** است و
   هیستوگرام به‌صورت پیش‌فرض روی محور لگاریتمی نمایش داده می‌شود.
۴. **آزمون تفاوت گروه‌ها**:
   - دو گروه (ریالی/تتری): **من‌ویتنی U** با تصحيح پیوستگی و تصحيح گره + اندازه اثر Cliff's δ.
   - چند گروه (چارک‌های نقدشوندگی، بازه‌های قیمتی، سطوح نوسان): **کروسکال-والیس H** با ε² به‌عنوان اندازه اثر.
   - مقایسه‌های دوبه‌دو: تصحيح **هولم** برای کنترل نرخ خطای نوع اول.
۵. **همبستگی**: اسپیرمن (رتبه‌ای) بین اسپرد و `log حجم`، `log قیمت`، `|تغییر روزانه|` و دامنه نوسان روز.
۶. **رگرسیون چندمتغیره (OLS)**: `ln(spread%) = β0 + β1·log10(حجم$) + β2·log10(قیمت$) + β3·|تغییر روز| + β4·IRT`
   — ضرایب، خطای استاندارد، t و p و R² گزارش می‌شود تا سهم هر عامل از بقیه جدا شود.
۷. **خوشه‌بندی**: k-means (با ++init و RNG قطعی) روی چهار ویژگیِ استانداردشده، و انتخاب k با معیار **Silhouette**.
۸. **عمق بازار**: از دفتر سفارشات، اندازه‌ی واقعیِ **تیک**، تیکِ نسبی، و **اسلیپیج**ِ سفارش‌های ۱۰۰ و ۱۰۰۰ دلاری
   (نسبت به قیمت میانی) محاسبه می‌شود.

## یافته‌های مورد انتظار (و چرا)

- **نقدشوندگی عامل اول است**: رابطه‌ی معکوسِ قوی بین `log حجم` و اسپرد (در داده شبیه‌سازی‌شده  ρ ≈ −۰.۹ و ε² ≈ ۰.۷۶
  برای چارک‌های حجم). در داده واقعی معمولاً β1 منفی و بزرگ است.
- **اندازه‌ی تیک کفِ مکانیکی می‌سازد**: نمادهای بسیار ارزان‌قیمت (مثل SHIB، BONK، DOGS در بازار ریالی) نمی‌توانند
  اسپردی کوچک‌تر از یک واحد تغییر قیمت داشته باشند؛ این جدای از نقدشوندگی است و در تب «عمق بازار» مستقیم اندازه‌گیری می‌شود.
- **بازار ریالی در برابر تتری**: کارمزد اسمیِ ریالی بالاتر است (۰.۲۵٪ در برابر ۰.۱۳٪ تیکر در سطح پایه)؛ اینکه اسپردِ
  خالص هم بیشتر هست یا نه، با آزمون من‌ویتنی در تب «تحلیل عوامل» و با عددِ δ مشخص می‌شود.
- **نوسان**: بازارهای پرنوسان‌تر معمولاً اسپردِ بیشتری دارند (ریسک موجودی بازارگردان)، اما اثر آن معمولاً از
  نقدشوندگی و تیک کوچک‌تر است.

- مقادیرِ اسپرد لحظه‌ای‌اند؛ برای تصمیمِ معاملاتی از ستون «ضریب تغییرات اسپرد» در نمونه‌برداریِ زمانی استفاده کنید.
- نرخ محدودیتِ API نوبیتکس ۲۰ درخواست در دقیقه است؛ فاصله‌ی نمونه‌برداریِ پیش‌فرض ۳۰ ثانیه است.
- جدول کارمزد ممکن است تغییر کند؛ در صورت نیاز از گزینه‌ی «سفارشی» در تنظیمات استفاده کنید.
