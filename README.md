# داشبورد تحلیل کارمزد و اسپرد نوبیتکس

تحلیل آماری **اسپرد** و **کارمزد** نسبت به قیمت در تمام نمادهای نوبیتکس، تشخیص تفاوت‌های معنی‌دار، تعیین عوامل مؤثر بر تغییر، و دسته‌بندی نمادها بر همان اساس.

## اجرا

```bash
npm install
npm run dev        # http://localhost:5173
```

ساخت نسخه نهایی: `npm run build` — ساخت اسنپ‌شات آفلاین: `npm run snapshot`

## منبع داده

| مورد | توضیح |
| --- | --- |
| دفتر سفارش | `GET https://apiv2.nobitex.ir/v3/orderbook/all` — همه بازارها در یک درخواست، بدون احراز هویت |
| کارمزد | [جدول رسمی نوبیتکس](https://help.nobitex.ir/knowledgebase/trading-fees/) — سطح پایه (Regular) |

| بازار | میکر | تیکر |
| --- | --- | --- |
| ریالی (IRT) | ۰.۲٪ | ۰.۲۵٪ |
| تتری (USDT) | ۰.۱٪ | ۰.۱۳٪ |
| سایر بازارها | ۰.۲٪ | ۰.۲٪ |

**زنجیره دریافت داده:** درخواست مستقیم ← سه پروکسی عمومی CORS ← اسنپ‌شات آفلاین داخل پروژه (`src/data/snapshot.json`) ← داده نمونهٔ عمداً ساختگی. منبع فعال همیشه در هدر داشبورد نمایش داده می‌شود.

> چون دریافت داده از سمت مرورگر انجام می‌شود، اگر مستقیم و پروکسی‌ها مسدود باشند، اسنپ‌شات محلی استفاده می‌شود. برای ساخت آن روی شبکه‌ای که به نوبیتکس دسترسی دارد: `npm run snapshot`.

## متریک‌ها

| متریک | فرمول | معنی |
| --- | --- | --- |
| اسپرد | `(بهترین فروش − بهترین خرید) ÷ قیمت میانه` | هزینه عبور از بازار |
| هزینه ورود | `اسپرد ÷ ۲ + کارمزد تیکر` | حداقل هزینه یک خرید بازار |
| رفت‌وبرگشت تیکر | `اسپرد + ۲ × کارمزد تیکر` | حداقل رشد قیمت لازم برای سربه‌سر |
| عمق | ارزش سفارش‌های ۱۰ سطح اول در هر دو سمت | توان اجرای سفارش بزرگ |
| تازگی | `now − lastUpdate` | اعتبار داده |

عمق بازارهای ریالی با نرخ `USDTIRT` و بازارهای بیت‌کوینی با `BTCUSDT` به دلار یکسان‌سازی می‌شود. بازارهایی که نرخ تبدیل ندارند با واحد ارز مقصد خودشان گزارش می‌شوند.

## روش تحلیل

**۱. توزیع آماری** — هیستوگرام اسپرد (رنگ‌بندی بر اساس چارک‌ها)، هیستوگرام کارمزد، خلاصه چارک/میانه/صدک ۹۵، نمودار جعبه‌ای هر سطح اسپرد. چون اسپرد دنباله راست دارد، آزمون‌ها روی لگاریتم اسپرد انجام می‌شود.

**۲. آیا تفاوت معنی‌دار است؟** — مقایسه هر جفت گروه با آزمون t ولچ روی لگاریتم اسپرد، همراه اندازه اثر Cohen. معنی‌داری = `p < 0.05` و `|d| ≥ 0.5`. گروه‌ها: ریالی↔تتری، تتری↔سایر، پرعمق↔کم‌عمق، تازه↔کهنه.

**۳. عوامل تغییر** — همبستگی رتبه‌ای اسپیرمَن اسپرد با: عمق، سطح کارمزد، تعداد سطوح دفتر سفارش، تأخیر داده، سطح قیمت، عدم توازن عرضه/تقاضا. خروجی به ترتیب شدت `|ρ|` مرتب می‌شود.

**۴. دسته‌بندی قوانین‌محور** — سه محور مستقل که مستقیماً از عوامل بالا می‌آیند:

- **سطح اسپرد** بر پایه چارک‌های ۲۵/۵۰/۷۵/۹۲ → تنگ، متعارف، باز، بسیار باز
- **سطح عمق** بر پایه سه‌ک‌وانتیل → پرعمق، متوسط، کم‌عمق
- **تازگی داده**

ترکیب این‌ها شش کلاس اجرا می‌سازد (پرعمق و کم‌هزینه، متعادل، تنگ ولی کم‌عمق، عمیق ولی گران، گران و کم‌عمق، دفتر سفارش نازک). علاوه بر آن، **امتیاز اجرا** از ترکیب نرمال‌شده اسپرد (۶۰٪) و عمق (۴۰٪) با جریمه تازگی محاسبه می‌شود.

## ساختار

```
src/
  lib/fees.ts        جدول کارمزد و تشخیص ارز مقصد از نماد
  lib/stats.ts       چارک، هیستوگرام، اسپیرمَن، t ولچ، اندازه اثر
  lib/nobitex.ts     زنجیره دریافت داده + اعتبارسنجی پاسخ
  lib/analytics.ts   متریک‌ها، دسته‌بندی، آزمون‌ها، عوامل
  components/        نمودارها، جدول، پنل‌ها
scripts/snapshot.mjs ساخت اسنپ‌شات آفلاین
```

## محدودیت‌ها

اسلیپیج، عمق لحظه اجرا، کارمزد سطوح بالاتر و تأثیر اندازه سفارش در محاسبات لحاظ نشده‌اند. اعداد فقط برای همان لحظه معتبرند و ابزار تحلیل‌اند، نه سیگنال معاملاتی.
